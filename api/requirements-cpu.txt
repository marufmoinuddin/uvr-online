# UVR Local CPU worker — Python 3.10
#
# The CPU counterpart of requirements.txt: same application, same model
# catalogue, same API — but torch from the CPU wheel index and no CUDA
# runtime at all. It is what the `cpu` compose profile and `run-local.sh
# --cpu` use.
#
# Kept as a separate file rather than a build argument on requirements.txt
# because the difference is not just a URL: the CPU image also drops the
# onnxruntime-gpu wheel for the much smaller CPU one, and pinning torch to
# the `+cpu` local version is what keeps pip from quietly resolving the CUDA
# build from PyPI.

# --- PyTorch (CPU) ---
# The CPU index is the PRIMARY index and PyPI is the EXTRA. Two rules worth
# knowing before touching this:
#
#   * The `+cpu` local version tag exists ONLY on download.pytorch.org —
#     PyPI hosts plain `torch==2.8.0`. The CPU index has to be listed
#     explicitly or the exact `==2.8.0+cpu` pin fails with "No matching
#     distribution found".
#   * A SECOND `--index-url` line is silently ignored by pip — only the last
#     one wins. Ordering indexes works only as --index-url (first) +
#     --extra-index-url (rest). Writing "CPU index, then PyPI" as two
#     --index-url lines quietly drops the CPU index entirely.
#
# The primary/extra order here is defensive rather than strictly required:
# the exact +cpu pin resolves either way round (CI installed it with the CPU
# index as the extra too), but keeping the CPU index first means an unpinned
# torch-shaped requirement can never pull a CUDA build from PyPI into a
# CPU-only image — unpinned resolution is exactly where a CPU image silently
# grows a 3 GB `cuda-toolkit` dependency.
#
# Verified on Python 3.10 (the interpreter the image and CI both use):
# torch-2.8.0+cpu, torchvision-0.23.0+cpu and torchaudio-2.8.0+cpu resolve
# from manylinux_2_28_x86_64 and NO CUDA packages are pulled in. Beware
# testing this file under a newer Python: there is no cp314 wheel for torch
# 2.8.0, so a resolve under 3.14 fails with "No matching distribution" even
# though the file is correct — easy to misread as an index bug.
#
# This matches api/requirements.txt (torch 2.8.0+cu128) — the two images run
# the same torch minor and differ only in the build (CPU vs CUDA).
--index-url https://download.pytorch.org/whl/cpu
--extra-index-url https://pypi.org/simple
torch==2.8.0+cpu
torchvision==0.23.0+cpu
torchaudio==2.8.0+cpu

# --- API ---
